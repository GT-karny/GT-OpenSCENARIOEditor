# GT_Sim gRPC service protos

These `.proto` files define the gRPC streaming services exposed by the GT_Sim
(esmini fork) backend:

- `service_groundtruth.proto` — `GroundTruthService.StreamGroundTruth` → `stream osi3.GroundTruth`
- `service_hostvehicledata.proto` — `HostVehicleDataService.StreamHostVehicleData` → `stream osi3.HostVehicleData`

## Source of truth

The **GT_Sim (esmini) fork is the single source of truth** for these service
definitions. The originals live in the fork at `proto/*.proto`, mirrored into
this repo via the `Thirdparty/GT_Sim` submodule
(`Thirdparty/GT_Sim/GT_esmini/proto/`). Do not hand-edit the copies in this
directory — they are regenerated by `scripts/sync-proto.mjs`.

## Sync procedure

```bash
# Optionally point at an external fork checkout:
#   GT_SIM_PROTO_DIR=/path/to/esmini/GT_esmini/proto
pnpm --filter @osce/esmini proto:sync   # copy from fork + rewrite OSI import path
pnpm --filter @osce/esmini proto:gen    # regenerate src/generated/osi.{js,d.ts}
```

## Why the copies are not byte-identical to the fork

The fork imports OSI messages with an `osi3/` path prefix
(`import "osi3/osi_groundtruth.proto"`), matching its build layout where the OSI
protos sit under an `osi3/` directory. This editor consumes OSI from the flat
`Thirdparty/open-simulation-interface` submodule, where the proto files live at
the directory root with **no `osi3/` prefix** (and their own cross-imports are
prefix-less too). No portable `pbjs`/`proto-loader` include-dir layout resolves
the prefixed path against the flat submodule, so `proto:sync` mechanically
rewrites `import "osi3/<name>.proto"` → `import "<name>.proto"` and prepends a
generated-file header. The `package`, `service`, and `rpc` definitions are
otherwise copied verbatim. This is the only divergence from the fork originals.

## Consumers

- Build-time codegen: `proto:gen` runs `pbjs`/`pbts` to produce
  `src/generated/osi.{js,d.ts}` (only `osi.d.ts` is committed; `osi.js` is a
  build artifact).
- Runtime: `src/client/gt-sim-grpc-client.ts` loads `service_groundtruth.proto`
  via `@grpc/proto-loader` with `includeDirs = [proto/, Thirdparty/open-simulation-interface]`,
  which resolves the prefix-less imports.
